# セキュリティの全体像

スミハジメのセキュリティ対策を、守るもの・境界・層ごとの対策・確認のしかたの順にまとめる。
報告の窓口は [`SECURITY.md`](../../SECURITY.md)、シークレットの扱いは [`docs/ops/secrets.md`](../ops/secrets.md)、
見つかった問題の一覧は [`findings.md`](findings.md)、判断の理由は [ADR-018](../adr/ADR-018-security-hardening.md)。

2026-10-02 に、書籍『Webアプリケーションセキュリティ入門』を基準に点検した（書籍の文章は引用しない）。
章の範囲で分けた 7 本の読み取り専用の監査で、高は 0 件、中が複数。修正は 2026-10-03 に本番とミラーへ反映した。

## 1. 何を守るか

このサービスにはログインが無く、氏名・電話・メール・完全な生年月日・マイナンバーを集めない（CLAUDE.md 原則 6）。
そのため、「アカウントの乗っ取り」や「保存した個人情報の漏えい」は主な脅威ではない。守るものは次の 4 つ。

| 守るもの                   | なぜ                                                                        | 壊れたときの影響                                             |
| -------------------------- | --------------------------------------------------------------------------- | ------------------------------------------------------------ |
| データの完全性と公式の根拠 | 全タスクに承認済みの公式ソースを付ける約束がこのサービスの中核（原則 2・5） | 利用者が誤った手続きに従う。改ざんされた根拠が公式に見える   |
| 可用性                     | 転入直後の期限つきの手続きに使われる                                        | チェックリストが開けず、期限を逃す                           |
| OpenAI の費用              | チャットは呼び出しごとに課金される                                          | 個人運営の予算を使い切られ、チャットが止まる                 |
| 利用者のプライバシー       | 質問や世帯の属性に、個人を特定できる情報が混じり得る（原則 7）              | 質問に書かれた電話・メールが外部（OpenAI）へ渡る。ログに残る |

世帯の属性は利用者の端末（localStorage）にだけ置き、サーバーには保存しない。

## 2. 信頼の境界

```
ブラウザ ──https──> Worker (Hono) ──> D1（公開済みデータ・台帳）
                        │            └> Vectorize（RAG の索引）
                        └──https──> OpenAI（埋め込み・回答生成。AI Gateway 経由も可）

オフラインのスクリプト（ingest・publish・build:index・eval）──https──> 自治体の公式サイト
```

- **ブラウザ → Worker**: 利用者の入力は全て信用しない。サーバーで検証する（スキーマ、上限、Origin）。画面側の検査は親切のためで、防御ではない。
- **Worker → D1 / Vectorize**: 公開できる状態（承認済み・有効期間内・同じ自治体・現行版）のデータだけを読む。Vectorize の結果も D1 と結合して絞る（二重のスコープ）。
- **Worker → OpenAI**: 送るのは質問と、検索で選んだ公式ソースの抜粋。キーを持つのは Worker だけ。送り先は許可リストで固定する。回答は信用せず、URL・電話・メールを根拠と照合してから返す。
- **オフラインのスクリプト → 自治体サイト**: 取得した HTML・xlsx は信頼しない入力として扱う。公式ホストの許可リスト、リダイレクトの再検査、サイズ上限、ハッシュ照合を通した後に、人の承認を経てデータになる。
- **取得原文 → 公開データ**: 原文、正規化データ、公開データを分ける（CLAUDE.md §4）。公開に使うのは人が承認したものだけ。

## 3. 層ごとの対策

| 層                 | 対策                                                                                                                                                                           | 場所                                                                  |
| ------------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ | --------------------------------------------------------------------- |
| 転送               | 平文 HTTP は 301 で https へ。書き込み系は 403。HSTS（1 年・サブドメイン込み・preload なし）。Cloudflare の Always Use HTTPS                                                   | `apps/api/src/canonical-host.ts` `headers.ts`                         |
| 入口               | 登録済みパスへの誤ったメソッドは 405 と `Allow`。未定義の API は JSON の 404。POST の Origin・Sec-Fetch-Site 検査                                                              | `apps/api/src/request-guards.ts` `index.ts`                           |
| ヘッダ             | CSP・nosniff・Referrer-Policy・COOP/CORP・Permissions-Policy を、301〜500 の全応答に付ける。POST とエラーは `no-store`                                                         | `apps/api/src/headers.ts`                                             |
| 流量               | Workers Rate Limiting（API 300 回/60 秒、チャット 10 回/60 秒。IPv6 は /64）。公開 GET のエッジキャッシュ 5 分。ごみ分別の品目一覧の isolate 内キャッシュ。チャットの 1 日上限 | `apps/api/src/rate-limit.ts` `edge-cache.ts` `db.ts` `wrangler.jsonc` |
| 入力               | Zod で境界を検証。ID の書式、文字数、許可リスト、日付の範囲。質問の個人情報検出                                                                                                | `packages/schemas` `packages/domain/src/personal-info.ts`             |
| データ             | 承認済み・有効期間内・同じ自治体・現行版だけを返す。公式ホスト判定（ポート・ユーザー情報を拒否）                                                                               | `apps/api/src/db.ts` `packages/domain`                                |
| RAG・LLM           | 区切りの無害化（抜粋にも適用）、`PROMPT_VERSION`、回答の URL・電話・メールの根拠照合、stale の警告、モデルの日付付き版固定、OpenAI の送り先の許可リスト                        | `packages/rag/src/prompt.ts` `apps/api/src/chat.ts`                   |
| 取得（オフライン） | リダイレクトを手動で追い 4 回まで。各ホップで公式ホストを再検査。5MB の上限。非表示要素の除去。xlsx はハッシュ照合後のみ、範囲制限つき                                         | `scripts/ingest/src/http.ts`                                          |
| 公開（オフライン） | スナップショットの SHA-256 照合、パスの封じ込め、SQL リテラルの検査、他自治体のソースを引く項目の検出、子プロセス引数の検査                                                    | `scripts/publish/src/snapshot-files.ts`                               |
| ログ               | 許可リストの項目だけ。IP・URL・質問は残さない。自動の invocation logs は止める。例外は種類だけ                                                                                 | `apps/api/src/log.ts` `wrangler.jsonc`                                |
| 画面               | https の URL だけをリンクにする。HTML に見える文字列は文字として表示。個人情報の送信前チェック                                                                                 | `apps/web`                                                            |
| 供給網・CI         | Actions の SHA 固定、`pnpm audit --prod`、Dependabot、install scripts の許可リスト、`minimumReleaseAge`                                                                        | `.github/` `pnpm-workspace.yaml`                                      |
| 窓口               | `SECURITY.md`、`/.well-known/security.txt`（RFC 9116）                                                                                                                         | `apps/api/src/security-txt.ts`                                        |

Worker の流量制限は、バインディングが無い環境（単体テスト・ローカル）では何もしない。制限の障害時は通す（fail-open）。
費用の総量は、チャットの 1 日上限と OpenAI 側の予算上限（未設定。SEC-40）が別に守る。

## 4. どう確かめるか

- **攻撃と正常の対**: 修正ごとに、攻撃を拒否するテストと、正常な使い方が通るテストを必ず対で置く。「全部を拒否する」変更でも攻撃側のテストは通ってしまうため。例: `apps/api/src/chat-hardening.integration.test.ts`、`entry-hardening.test.ts`。
- **ルートの棚卸しテスト**: `apps/api/src/routes.test.ts` が、登録済みの全ルートを一覧と突き合わせる。新しいルートを足すと一覧と合わずに落ちるので、入口の検査（ヘッダ・405・Origin・流量）を通るかを足した人が確かめることになる。一覧の全ルートを実際に叩いて確認もする。
- **E2E の CSP テスト**: `tests/e2e/tests/security.spec.ts` が、実際のブラウザで CSP 違反が出ないことと、主要な画面が動くことを確かめる。
- **規模**: 単体テスト 3,100 件超と E2E 87 件が通っている（2026-10-03 時点）。

## 5. テストの方針

- **能動的なセキュリティテスト（攻撃を模した要求）は、ローカルかミラーだけで行う。**
- **本番（sumihajime.com）には、通常の利用と同じ無害な要求だけを送る。** 例: `GET /api/health`、画面の表示、`curl -I`。
- **負荷試験・総当たり・自動スキャナの大量アクセスはしない。** 本番でもミラーでも。ミラーは大会提供のアカウントで、予算と無料枠が別にある。
- 個人情報に見える値を本番へ送らない。テストには明らかな架空の値を使う。
- 報告者へのお願いも同じ内容を `SECURITY.md` に書いてある。
