# 検証レポート（V1）— スマホアプリ版の需要調査

- 検証日: 2026-09-30
- 検証者: Verification Agent V1（startup-design）
- 対象（8ファイル）: `00-intake/` の brief・preflight・brainstorm、`01-discovery/` の market-analysis・competitor-landscape・target-audience・industry-trends・confidence-dashboard
- 照合先: `01-discovery/raw/` の A1・A2・B1・B2・C
- 方法: 成果物を全文読み、数値・日付・引用を raw と突き合わせた（42件、末尾の表）。raw 以外の一次資料は確かめていない（Web へは取りに行っていない）。
- 行番号は、検証時点の各ファイルの行。

**要約**: 結論の向き（「フルのネイティブアプリは今は作らない」）は raw 全体と合っており、下の「重大」を直しても変わらない見込み。ただし次の問題が残る。

- SOM の基準値が raw 内で矛盾している
- raw にある、結論と逆向きの証拠と、集客の Red flag が抜けている
- B2B の読み方が raw と逆になっている
- 東京アプリについての確信度が高すぎる
- 最も近い競合との差が raw に記録されていない

このままでは Gate を通す根拠として弱い。

## 重大

### 重大1：引越れんらく帳の利用者数が raw 内で約36倍違い、成果物は片方しか使っていない（チェック2・3・8）

- **該当箇所**
  - preflight.md L7「引越れんらく帳（電気・ガス・水道等の一括連絡と転出届、「年間12万人」は日付の無い自社主張）[Data, Tier 3]」
  - market-analysis.md L19「基準は引越れんらく帳の自称「年間12万人」≒全国の約2%（日付の無い自社主張、Tier 3）」
  - competitor-landscape.md L15「自称「年間12万人」」
  - confidence-dashboard.md L33「引越れんらく帳・引越し侍など主要な比較対象の利用者数は自社主張で、日付が無い。」
- **何が問題か**
  - raw/B2 §1 #4 には、運営会社（TEPCO i-フロンティアズ）の2024-06-05の発表として「**2023年度（2023-04〜2024-03）に440万UU以上**」がある。[Data, STALE] の扱いで、B2 はこれを代替手段の到達規模の3位に置いている。
  - 成果物はこの数字に一度も触れていない。日付の無い「年間12万人」だけを使い、SOM（0.5〜5%）の上限の根拠にしている。
  - ダッシュボードの「日付が無い」は、B2 の日付つきの数字と合わない。
  - 2つの数字は、測っているもの（サイトのUUか、サービスの利用者か）が違う可能性が高い。その説明が無いまま、片方が落ちている。
- **影響**
  - 次の推論が、Tier 3 の自称値1つと前提だけで成り立っている。SOM → 月間利用者（ネイティブ130〜500人）→ market-analysis L43 の Red「2つのネイティブのコードベースを利用者数で正当化できない」。
  - このため confidence-dashboard.md L22「**判断の決め手には Tier 3 だけを使っていない**」は、少なくともこの Red には当てはまらない。
- **直し方**
  - 2つの数字を並べて書く。12万人は日付の無い自称。440万UUは2023年度・2024-06発表で古く、単位はUU。
  - SOM の基準は「弱い」と明記する。
  - market-analysis の Data Gaps に「引越れんらく帳の、日付があり、UUではない利用件数」を足す。
  - ダッシュボード L33 の「日付が無い」を正す。L22 は「SOM と月間利用者の推計は、Tier 3 と前提に依存する」に改める。

### 重大2：集客の証拠と Red flag（B2 §2d・§4・Red 2）が、どの成果物にも入っていない（チェック8）

- **該当箇所**
  - brief.md L26「国内のみのため Wave 4（流通）は省いた」
  - 関係する記述は competitor-landscape.md L37「アプリの発見経路はストア検索ではなく Google 検索・不動産会社・区のサイト・東京アプリ。…[Data]」の1行だけ。
- **何が問題か**
  - Wave 4 を省いたので、流通の証拠は B2 にしか無い。その B2 の Red 2「ネイティブは、実際に効く集客経路（QR・リンク・短尺動画・SEO）を傷める」と、裏づけの数字が抜けている。
  - 抜けている数字と論点:
    - Apple Ads（日本）の数字（Adapty、2026年）: タップからインストールへの転換率49.28%（世界の中央値62%より低い）、CPA $1.49。
    - Apple Ads で1,000インストールを得るのに約¥22万かかる [Estimate]。ただし、ストアに検索量がある場合の話。
    - 最初の1,000人を運ぶ経路（短尺動画・入居資料のQR・人事や学生団体・SEO）は、どれも URL で届く。ストアの自然流入は、この分野では極めて小さい。
    - 管理会社は2つ目のアプリを配るより、自社の LINE やアプリの中にリンクを置くことを好む（B2 §3a）。
  - 「アプリにすると何を失うか」を数字で示した証拠はこれしか無い。作るかどうかの判断に直接効く。
- **直し方**
  - competitor-landscape.md に「5. 集客：アプリにすると失うもの」の節を足し、上の数字に [Data, Tier 3] または [Estimate] を付ける。
  - Flags に Red「ネイティブ版は、リンクで届ける集客経路に約半分の離脱を足す」を足す。
  - ダッシュボードに1行足す（確信度 Medium。ベンダー1社のベンチマークのため）。
  - brief L26 に「集客の一部は B2 が扱った」と注記する。

### 重大3：アプリに有利・PWA に不利な証拠が落ちていて、需要の判断が一方に偏っている（チェック3・8）

- **該当箇所**
  - target-audience.md L3「アプリへの需要は代理指標しか無い」
  - industry-trends.md L26「ホーム画面への追加方法を知っている人は21.5%、ストアのアプリを信頼31.7%・ホーム画面のWebアプリ2.0%（2026-04・n=200・ベンダー調査、弱い証拠）。[Data, 弱]」
  - target-audience.md L39「必要なサービスでもアプリを入れたくない27.3%・サービスを諦めることがある14.7%」
- **何が問題か**：raw にある次の数字が、成果物のどこにも無い。
  - A2 §3 Pentagon 調査（2026-04、n=200）
    - 選べるならネイティブ48.3%、Web 版7.3%
    - ストアに無いアプリは不安 72.7%
    - ホーム画面に追加した人の47.6%は、もう使っていない（案B に不利）
  - C §5 System Research 調査（n=300）: 「必要ならダウンロード」53.0%と「抵抗なく」5.0%で、**58%は必要なら入れる**。成果物は否定側の27.3%・14.7%しか引いていない。
  - A2 §3 Pushwoosh（2025年）: iOS のネイティブのプッシュ許可率56.36%（ベンダーの数字）。
- **評価**
  - どれも弱い証拠。それでも「代理指標しか無い」は事実と違う。弱いが、直接に好みを聞いた調査があり、結果はアプリ寄り。
  - 案B（PWA）の弱点（ホーム画面に追加しても47.6%が使わなくなる）も見えなくなっている。
  - 調査の問い「Web を磨くか、アプリを作るか」の比較に直接かかわる。
- **直し方**
  - target-audience.md §5「作る理由」に次を足す。Pentagon の48.3%対7.3%と72.7%、System Research の58%。ラベルは [Data, 弱・Tier 3・利害あり]。
  - L3 は「直接に好みを聞いた調査は弱いものが1件でアプリ寄り。行動の指標（検索・インストール数・レビュー）はアプリに不利」に直す。
  - brainstorm.md 案B の「危うい点」と、ダッシュボードに、「追加後に47.6%が使わなくなる」を足す。

### 重大4：B2B の信号を Green にしているが、B2 は同じ事実から Red と判定している（チェック2・3）

- **該当箇所**：market-analysis.md L46「**Green**: …B2B（入居時の導線を持つ事業者）にはお金が流れている。」
- **何が問題か**
  - raw/B2 の Red 1 は、同じ事実を逆に読んでいる。
    - 入居の時点は、既に1入居者あたり約¥7,000で収益化されている。スマサポは1件あたり¥7,147を285,404件、仲介会社への紹介料は1件最大¥8,000。
    - 取次をしない無料ツールには、事業者へ分けるお金が無い（インセンティブが合わない）。
    - ネイティブ版は B2B の提案に何も足さない（B2 §3a）。
  - A1 は前向きに、B2 は否定的に読んでいる。成果物は A1 の読みだけを採った。
  - これは brief L16 のロードマップ「B2Bが本命」に直接かかわる。
- **直し方**
  - Green を「お金は流れているが、取次をしない無料ツールには分けるお金が無い（B2 Red 1）」に改め、Yellow か Red に移す。
  - スマサポの数字（logmi、2025-11-19）を [Data, Tier 2/3] で足す。

### 重大5：東京アプリの計画を「一次資料・確信度 High」とし、「期限のプッシュ通知」と同じものとして扱っている（チェック3・4・7）

- **該当箇所**
  - industry-trends.md L3「確信度: **High**（規約・都の発表は一次資料）」
  - industry-trends.md L8「→ ネイティブ版の最大の売り（期限のプッシュ通知）を公式が先に持つ。」
  - industry-trends.md L43「**Red**: 東京アプリの計画がネイティブ版の最大の利点（通知）と重なる。」
  - confidence-dashboard.md L9「東京アプリが通知（2026下期）・区市町村手続きの案内（2028年度〜）へ広がる | **High** | 都の発表と報道（一次資料）」
- **何が問題か**
  1. 計画の文言の出典は、raw/A2 §1.2 ではデジタル行政（業界紙、2026-06-17）で、「ITmedia と整合」とあるだけ。都の2026-06-04の報道発表は、DL数の出典として使われている。計画の文言そのものは、都の一次資料で確かめていない。業界紙2つは同じ発表を報じたもので、互いに独立した裏づけにはならない。
  2. 計画の文言は「居住地のエリアや年齢層に応じた情報のプッシュ配信」。引越し日から計算した、個人ごとの期限の通知ではない。raw/B1 の DATA GAP にも「東京アプリのロードマップに引越しのチェックリストがあるか」は不明とある。「最大の売りを公式が先に持つ」は、raw の文言より強い言い方になっている。
  3. 「令和10年度以降は…順次拡大」は計画で、実施されるかは確かではない。
- **直し方**
  - ダッシュボードの確信度を2つに分ける。
    - 発表があったこと: Medium–High。業界紙経由で、都の原文は未確認のため。
    - 個人の期限通知と重なること: Low–Medium。
  - 計画の文言を、都の一次資料（事業計画や報道発表の原文）で確かめる。
  - L8 と L43 は「地域・年齢別の配信が始まる。個人の期限通知と重なるかは未確認」まで弱める。
  - B1 の上のギャップを、industry-trends と competitor-landscape の Data Gaps に移す。

### 重大6：くらしぽーたルとの差（「期限の計算は無い」）が raw に記録されておらず、B1 の網羅性も実際より高く書かれている（チェック3・4・5）

- **該当箇所**
  - competitor-landscape.md L16「東京53＋神奈川33自治体・602ページ | ×（**自治体ごとの手続きガイド。引越し日・世帯からの期限計算は無い**）」
  - competitor-landscape.md L35「（くらしぽーたルは出典と確認日を付けるが、個別の期限計算は無い）」
  - confidence-dashboard.md L7「ストア・Web の網羅的な調査（B1）＋くらしぽーたルの公式サイトでの確認。」
- **何が問題か**
  - くらしぽーたルは raw/B2 §3d にしか出てこない。B2 は「B1 に比較を回す」と書いたが、B1 にくらしぽーたルの項目は無い。
  - 成果物にある次の内容は、どの raw にも無い。統合のときに確かめたものらしいが、根拠の記録が残っていない。
    - 「期限計算は無い」
    - 「602ページ」
    - 「すべてのページに出典と確認日をつけています」
    - 「アプリは現在準備中」
  - 「〜は無い」という主張には証拠が要る。しかもこれは「中身では勝っている」という差別化の、唯一の柱になっている。
  - B1 は見出しで「タスクごとに公式の出典と最終確認日を付けるものは無い」と書いたが、B2 がくらしぽーたルを見つけたことでこの主張は崩れた。つまり B1 は網羅できていなかった。ダッシュボードの「網羅的な調査（B1）」は実態と合わない。
- **直し方**
  - raw/B1 に「§1-13 くらしぽーたル」を追記する。URL、取得日、確かめたページ（例: 港区の手続きページ）の該当箇所、期限の計算が無いとどう確かめたかを残す。
  - ダッシュボード L7 は「B1 はくらしぽーたルを見落とし、B2 が見つけた。網羅できているかは未確認」に直し、確信度を Low–Medium に下げる。

### W4：東京の転入者数の分母が、ファイルごとにそろっていない（チェック2）

- **何が問題か**
