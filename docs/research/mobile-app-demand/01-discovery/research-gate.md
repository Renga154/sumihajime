# Research Gate（継続判断）

## 判定

| 案                                                                      | 判定          | 理由                                                                                                                                                                                                                                             |
| ----------------------------------------------------------------------- | ------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| A. フルのネイティブアプリ（iOS＋Android）                               | 🔴 **Red**    | 需要（検索・ストアの実績）が弱く、同時利用が少なく、収益も増えない。大手は撤退済み。リンクで届ける集客経路にインストールの離脱（約半分）を足す。好みを聞く弱い調査はアプリ寄りだが、行動の指標はアプリに不利                                     |
| B. Web をアプリに近づける（PWA＋Web Push＋家族共有＋匿名の計測）        | 🟢 **Green**  | 痛み（期限・自分に必要な手続き）は強く、中身の差別化は Web のまま効く。集客経路（検索・QR・動画）を壊さない。追加コストが小さい。弱点: ホーム画面への追加方法を知っている人は21.5%、追加した人の47.6%はもう使っていない（弱い証拠）→ 実験3で測る |
| C. iOS だけの小さな相棒アプリ（通知・ウィジェット・カレンダー書き込み） | 🟡 **Yellow** | 需要の根拠としては弱い（中位でネイティブ全体が月130〜500人、iOS だけならその一部。狙う子育て世帯は対応範囲で約1.2万世帯/年と小さい）。ただしポートフォリオ目的なら、4.2 を満たす範囲に絞れば正当化できる                                         |

## いちばん強いシグナル

- 痛みは強く、毎年同じ時期に来る（「転入届」の検索は3月に2.32倍、東京の転入届は年約108万人）。[Data]
- 自治体・世帯ごとの期限を公式根拠つきで出す民間サービスは他に見つからなかった。[Data + Opinion — 確信度 Low–Medium。網羅の漏れはありうる]
- 個人情報を取らないことは、営業電話を嫌う利用者に効きうる。[Opinion — 古いレビュー数件が根拠]

## いちばん強い懸念

- 「引越し 手続き アプリ」の検索需要はほぼゼロ。専用アプリの最上位でも iOS 評価650件、リクルートの専用アプリは撤退。[Data]
- 使うのは1回の引越しで6〜8週間。同時に使う人が少なく、入れたアプリは消される。[Estimate / Data]
- 東京アプリ（640万DL）が2026年10月から地域・年齢別のプッシュ配信、2028年度以降に区市町村の手続き案内へ広げる計画（業界紙の報道）。個人の期限通知と重なるかは未確認。[Data, Tier 2]
- 入居の時点は既に取次で収益化されていて（1入居者約¥7,000）、取次をしない無料ツールは B2B で分けるお金を持たない。アプリにしてもこれは変わらない。[Data + Opinion]

## 条件（Yellow の C を進めるなら）

- 検証実験1（聞き取り）で「期限を自分で管理していた」行動が確認できること。
- 検証実験3（Web Push）で通知の申し込みが一定以上あること（`06-validation/kill-criteria.md`）。
- 4.2 を満たすネイティブ独自の機能（通知・ウィジェット・カレンダー書き込み・オフライン）に絞り、データはサーバーから読む（ストア審査で公式情報の修正が遅れないように）。

## 創業者（運営者）への問い

スキルの手順ではここで「全体の戦略へ進む／方向転換／中止」を選ぶ。本調査の推奨は **「ストアのアプリは作らず、Web（B）に方向転換。ポートフォリオ目的の C は、検証実験の結果を見て2027年1月に判断」**。
