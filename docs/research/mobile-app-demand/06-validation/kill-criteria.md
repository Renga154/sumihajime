# 中止・方向転換の条件（ネイティブアプリ）

次のどれかに当たったら、ネイティブアプリは作らない（または撤退する）。サンクコストで判断を曲げないために、先に決めておく。

1. **聞き取り**（実験1）で、手続きのためにアプリを入れて使い続けた人が10人中**2人未満**、かつ期限を自分で管理する工夫をしていた人が**4人未満**。
2. **件数の計測**（実験2）で、`.ics` 書き出しか通知ボタンがチェックリスト作成の**5%未満**（2027年1〜4月）。
3. **Web Push**（実験3）の申し込みが、日付つきの期限があるチェックリストの**3%未満**。
4. **東京アプリ**が、公開前に引越し手続きの期限の通知か区市町村の手続き案内を始めた場合。アプリは作らず、公式側へのデータ提供・連携に方向転換する。
5. 作った場合でも、**Apple の審査で 4.2 を理由に2回却下**されたら、PWA に戻す。
6. 公開後、最初の繁忙期（3〜4月）の**ネイティブの月間利用者が200人未満**なら、保守の負担に見合わないとして Web に一本化する。
7. ストア審査のせいで、**公式情報の修正がアプリだけ3日以上遅れた**ことが1回でもあれば、データをサーバーから読む作りへ直すまで配布を止める。
