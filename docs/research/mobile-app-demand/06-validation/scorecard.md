## 結論（Verdict）

**重大な懸念あり（4〜5点）。今はストアのネイティブアプリを作らない。** 需要の実態は「期限が分かるリスト」にあり、それは Web で既に提供しており、アプリにしても利用者も収益も増える根拠が無い。
代わりに Web を「アプリのように」する（ホーム画面への追加・期限前日の通知・家族との共有）と同時に、**需要を測る仕組み**（聞き取りと、個人を特定しない件数だけの計測）を入れ、2027年春の実績で改めて判断する。

**ポートフォリオとしての判断は別にする。** 行政向けDXのポートフォリオとしてネイティブの実績が欲しいなら、iOS だけの小さな相棒アプリ（Web のリストを読み込み、期限の通知・ウィジェット・カレンダー書き込みだけをする）は、需要ではなく学習と実績のための投資として筋が通る。その場合も「需要に応えるため」とは説明せず、検証実験1〜3の結果を見てから着手する。

## Flags

- **Red**: 利用者が通知やアプリを求めているという直接の証拠が無い（聞き取り・計測が未実施）。
- **Yellow**: 目的（使われる／ポートフォリオ）が混ざると、需要の弱さを見落としたまま作りがち。
