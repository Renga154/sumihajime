# 検証実験（安い順・上位3つ）

スキルの規則どおり、顧客への聞き取りを先送りしたので**実験1は聞き取り**。

## 実験1: 過去1年に東京へ転入した人への聞き取り（10人、子育て世帯を半数以上）

- **確かめる前提**: 転入者は期限の管理に困っていて、自分で工夫（メモ・カレンダー・アプリ）をしていた。通知が来るなら使った。
- **方法**: 20〜30分のオンライン面談。仮定の質問（「アプリがあったら使いますか」）はせず、**過去の行動**を聞く。
  1. 最後の引越しで、役所の手続きで困ったのは何でしたか（最初にこちらから例を出さない）
  2. 期限をどうやって把握・管理しましたか（見せてもらえるならメモやカレンダーを見る）
  3. 手続きのためにアプリを入れたことはありますか。今も入っていますか。消したなら、いつ・なぜ
  4. 期限を過ぎた・過ぎそうになった手続きはありましたか。何が起きましたか
  5. 家族とどう分担・共有しましたか
- **募集**: 知人・X・note での募集、子育てコミュニティ。謝礼は無しかAmazonギフト500円程度。個人情報は記録しない（仮名でメモ）。
- **合格**: 10人中**8人以上**が、こちらから言う前に「何が必要か・いつまでか分からない」問題を挙げる。**4人以上**に行動のシグナル（自分でリマインダーを作った・アプリを入れた・期限を過ぎて損をした）がある。
- **アプリ判断用の指標**: 手続きのためにアプリを入れ、使い続けた人の数。
- **期間・費用**: 2週間・ほぼ0円。

## 実験2: 個人を特定しない件数だけの計測（Web）

- **確かめる前提**: 利用者は期限を「自分の外」（カレンダー・通知）に持ち出したい。引越し後も戻ってくる。
- **方法**: 解析ツールは入れず、サーバー側で**日ごとの件数だけ**を数える（チャットの1日上限と同じ仕組み）。数える操作は、チェックリストの作成・`.ics` 書き出し・印刷・端末内の控えの表示・「期限を通知」ボタン。IP・端末IDは保存しない。プライバシーポリシーを先に改定する。
- **合格**: チェックリスト作成の**15%以上**で `.ics` 書き出しか通知ボタンが押される。
- **期間・費用**: 実装1〜2日、計測は2026年12月から。判定には2027年1〜4月の数字を使う（`kill-criteria.md` の2と同じ期間）。

## 実験3: 期限の前日に通知（Web Push）— 偽の扉から本物へ

- **確かめる前提**: 通知は、ネイティブにしてでも欲しい機能である。
- **方法**: チェックリストに「期限の前日に通知を受け取る」を置く。Android・パソコンは Web Push を実装、iPhone はホーム画面への追加の案内から Web Push（iOS 16.4〜、iOS 26 はホーム画面のサイトを既定でWebアプリとして開く）。通知は端末に保存した期限から作り、個人情報は送らない。
- **合格**: 日付つきの期限があるチェックリストの**10%以上**が通知を申し込む。iPhone でホーム画面への追加に進む人が一定数いる（案内を見た人の20%以上）。
- **不合格**: 3%未満。
- **期間・費用**: 実装1週間、計測は2027年1〜4月。

## その後

実験1〜3がすべて合格し、かつ iPhone のホーム画面への追加が壁になっている（案内を見ても進まない）と分かった場合に限り、**iOS だけの小さな相棒アプリ（案C）**を検討する。

## Flags

- **Yellow**: 実験2・3は2027年春の繁忙期まで十分な件数が集まらない。判断は2027年4〜5月になる。
- **Yellow**: 計測を入れること自体がプライバシーポリシーの変更で、原則（ログに個人情報を残さない）を守る設計の確認が要る。
