# スマホアプリ版の需要調査（2026-09-30）

**問い**: スミハジメの iOS / Android のネイティブアプリ版に需要はあるか。Web を磨くより作る価値があるか。
**方法**: [startup-skill](https://github.com/ferdinandobons/startup-skill) の `startup-design`（Fast Track に需要シグナルの調査を追加）。5つの調査エージェントで Web を調べ、統合後に検証エージェント（V1）が数値42件を照合し、指摘（重大6件）を直した。
**結論**: **今はストアのネイティブアプリを作らない（総合 4/10）。Web をアプリに近づけ、需要を測ってから2027年春の実績で再判断する。**

## 主な発見（詳細は各文書）

1. **痛みは強いが、アプリの需要は弱い。** 「転入届」の検索は3月に2.32倍。一方「引越し 手続き アプリ」の検索は Google Trends でほぼ0。専用アプリの最上位でも iOS 評価650件、リクルートの専用アプリは撤退。
2. **同時に使う人が少ない。** 1回の引越しで使う期間は6〜8週間、入れたアプリは消される（アプリ疲れの調査、弱い証拠）。
3. **アプリにすると集客で失う。** 最初の利用者を運ぶ経路（検索・QR・短尺動画）はすべてリンク。インストールで約半分が離れる。
4. **中身は独自。** 引越し日・世帯から期限を計算し、公式根拠を付ける民間サービスは他に見つからなかった（最も近いくらしぽーたルは86自治体で出典と確認日を付けるが、期限の計算は無い）。
5. **アプリ寄りの証拠もある**（選べるならネイティブ48.3%・Web 7.3%、ストアに無いアプリは不安72.7%。いずれも n=200 のベンダー調査で弱い）。PWA にも弱点（ホーム画面に追加した人の47.6%はもう使っていない）。

## 次にやること（`06-validation/`）

1. 過去1年に東京へ転入した10人への聞き取り（子育て世帯を半数以上）— 2週間・ほぼ0円
2. 個人を特定しない件数だけの計測（チェックリスト作成・`.ics` 書き出し・通知ボタン）— プライバシーポリシーの改定が先
3. 期限の前日の通知（Web Push）を Web に実装して申し込み率を測る — 2027年1〜4月

中止・方向転換の条件は `06-validation/kill-criteria.md`。ポートフォリオ目的で iOS の小さな相棒アプリを作る判断は、需要とは別に `06-validation/scorecard.md` の結論に書いた。
