# 運用手順: 再監査（「再確認中」になった公式ソースを確かめ直す）

定期巡回（ADR-014、`docs/ops/drift-check.md`）が公式ページの更新・不達を検知すると、そのソースを根拠に
持つ手続きは「再確認中」になる。**解除できるのは人の再監査だけ**。この文書はその手順。

## 実測（2026-09-25、初回の全件巡回で溜まった73件）

| 工程                                                   | 所要                   |
| ------------------------------------------------------ | ---------------------- |
| 再取得・差分・数の事実の照合（`reaudit report`、73件） | 72秒（機械）           |
| 差分を読み、公開文言と突き合わせる（73件）             | 約15分                 |
| 公開文言の修正（10件）とテスト更新                     | 別途（修正の量による） |

73件の内訳: 公開文言の修正が要ったもの **10件**／リンク切れ・移転 **3件**（うち誤検知1）／
公開文言に影響しない更新 **60件**（医療証の更新案内、ナビ・お知らせの入れ替え、様式PDFの差し替え、
CSVの文字コード変更など）。**1件あたりの判断はほぼ「読んで無関係と確かめる」作業で、重いのは
公開文言に効く1割強だけ**。

## 手順

1. **対象を取る。** 本番 D1 から効力のある検知の一覧を取る（SQL は `docs/ops/drift-check.md` §2）。
2. **報告を作る。** リポジトリには何も書かない。
   ```sh
   pnpm --filter @tmn/ingest reaudit report --ids <id,id,...> --out <作業ディレクトリ>
   ```
   `report.md` に、ソースごとの差分（更新日の行は除外）、引用している手続き、公開文言に含まれる
   **数の事実**（◯日・◯か月・◯歳・◯月◯日・◯円）が承認時／現在の原文にあるかが出る。
3. **全件の差分を読む。** 機械の見立て（`unchanged` / `no-fact-loss` / `fact-lost`）は入口にすぎない。
   - **数の照合は「消えた数」しか拾えない。** 2026-09-25 の杉並区は「15日以内」を残したまま
     「10月1日以降の転入は3カ月以内」を**追加**しており、照合は通ったが公開文言は誤りになっていた。
     期限・対象・窓口・持ち物・電話番号の**追加や条件分岐**は読んで見つけるしかない。
   - 差分に出た語で、その区の公開文言（`data/normalized/<区>/procedures.json` の
     dueDescription・requiredDocuments・locations・contact・cautions）を検索して当てる。
4. **分類する。**
   - 公開文言に影響なし → 台帳の再承認だけ。
   - 公開文言が誤りになった → 正規化データ（と必要ならルール）を直す。手続きの `version` と
     `lastVerifiedAt` を再監査日へ、ルールを変えたら `ruleVersion` も上げる。回帰ガードのテストが
     承認日を固定しているので、`packages/rules/src/reaudited.fixture.ts` に手続きを足す。
   - リンク切れ（404）→ 区サイトの索引・サイト内検索で移転先を探す。**同名ページへの単純な移転**なら
     台帳のURLを直す。内容が別ページへ統合されていたら、そのページで公開文言を読み直す。
   - 公式ページ同士で食い違う → 推測で片方を選ばない。**より個別のページ**（施設ならその施設の
     ページ、手続きならその手続きのページ）と更新日を確かめる。2026-09-25 の花畑区民事務所は、
     区民事務所一覧の案内ページが古く、施設ページに前日付の仮設移転が載っていた。
5. **人の承認を得る。** 修正内容と「影響なし」の判断をまとめて示し、承認を得る
   （承認の出どころはコミットと台帳の注記に書く）。
6. **反映する。**
   ```sh
   pnpm --filter @tmn/ingest reaudit apply --result <作業ディレクトリ>/result.json --ids <承認したid> --approval "<承認の出どころ>"
   ```
   report で取得した**そのバイト列**を版付きスナップショット（`<id>.<YYYYMMDD>.<ext>`）として保存し、
   台帳のハッシュ・ページ更新日・取得日・最終確認日・注記を更新する（再取得はしない）。
   URL が変わったものは台帳の `source_url`（と `source_title`）も直す。
7. **テスト → publish → デプロイ。** `pnpm run test` の後、`publish:local -- --remote`（正典・ミラー）。
   台帳の最終確認日が検知時より新しくなるので、「再確認中」は自動で外れる。
   `/api/health` の `drift.flaggedSources` が減ったことを確かめる。

## 誤検知として分かっているもの

- **ファイルのダウンロードが別ホストへリダイレクトする**（渋谷区の ArcGIS Hub）。配信基盤の仕様で、
  ページが消えたわけではない。2026-09-25 から csv/xlsx はホスト・パスを見ず、HTTP の成否と中身の
  ハッシュだけで判定する（`packages/drift/src/classify.ts`）。
- **CSV の文字コードだけ変わる**（品川区・板橋区が UTF-8 BOM 付き → Shift_JIS に保存し直した）。
  生バイトのハッシュは変わるが中身は同一。報告では `unchanged` と出るので、再承認して新しい
  ハッシュを記録すればよい。
