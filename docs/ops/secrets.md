# シークレット運用

シークレットは **名前だけ** をここに書く。値・値の一部・先頭数文字も、このリポジトリ・Issue・チャット・ログに書かない。

## 1. 棚卸し（名前のみ）

| 名前             | 用途                                                   | 置き場所                                                                                                                                     |
| ---------------- | ------------------------------------------------------ | -------------------------------------------------------------------------------------------------------------------------------------------- |
| `OPENAI_API_KEY` | RAG回答生成（AI Gateway 経由）。チェックリストには不要 | Cloudflare Worker secret（`apps/api/wrangler.jsonc` の各環境: 既定の `app` と `--env odh` の `sumihajime`）／ローカルは `apps/api/.dev.vars` |

- ローカルの `apps/api/.dev.vars` は `.gitignore` 済み（`.dev.vars` / `.dev.vars.*`）。権限は `chmod 600`。
- `wrangler.jsonc` の `vars` に入れてよいのは非機密の設定だけ。キーは必ず Worker secret にする。
- wrangler は環境ごとにシークレットを継承しない。環境が増えたら環境ごとに投入する。
- 新しいシークレットを追加したら、この表に名前・用途・置き場所を足す。

## 2. 誰が設定するか

オーナー本人が自分の端末で `wrangler secret put` を実行する。エージェント（Claude Code など）には投入させず、値を渡さない。エージェントに `.dev.vars` を読ませない。

## 3. ローテーション手順

定期（目安: 半年に1回）と、担当端末の紛失・退職相当の変更があったときに行う。

1. OpenAI ダッシュボードで新しいキーを作成する（下記の推奨設定を適用）。
2. 環境ごとに投入する。値は対話プロンプトに貼る（コマンドライン引数やシェル履歴に残さない）。
   - 既定環境: `wrangler secret put OPENAI_API_KEY`（`apps/api` で実行）
   - ミラー環境: `wrangler secret put OPENAI_API_KEY --env odh`
3. ローカル用は `apps/api/.dev.vars` を新しいキーに書き換える（`chmod 600` を維持）。
4. `/api/chat/availability` を各環境で確認し、チャットが利用可能と返ることを確かめる。
5. 動作確認後に、OpenAI ダッシュボードで **古いキーを失効** させる。
6. 失効後に再度 `/api/chat/availability` を確認する。

## 4. 推奨設定

- 環境ごとに別のキーを使う（本番／ミラー）。ローカルのビルド・評価（eval）用も本番と分ける。1つ漏れても他へ波及しない。
- OpenAI の **プロジェクト単位のキー** を使い、使えるモデルを必要最小限に制限する。
- 月額の予算上限（budget limit）と通知を設定する。上限到達時はAPIが止まってもチェックリストと公式リンクは使える設計（CLAUDE.md 原則8）。
- キーをチャット・ログ・Issue・PR・スクリーンショットに貼らない。誤って貼ったら漏えいとして扱う。
- CI（GitHub Actions）にはキーを渡さない。依存導入とテストの job は秘密情報なしで動く。

## 5. 漏えいしたとき

順序が重要。

1. **まず失効**: OpenAI ダッシュボードで該当キーを即座に失効させる。
2. **次にローテーション**: 上記3.の手順で新しいキーを作り、各環境へ投入する。
3. **最後に利用状況を確認**: 失効前後の使用量・リクエストに身に覚えのないものがないか確認する。予算上限が効いていたかも見る。
4. 漏えい経路（履歴・ログ・共有物）を特定して除去し、再発防止をここに追記する。Git履歴に入った場合、履歴を消しても過去の複製は残るので、失効が唯一の対処になる。
